If a MongoDB repository is needed later, I would create a new `MongoAccountRepository.java` file that implements `AccountRepository`. Main would only need its repository construction line changed to use the new implementation. Bank would not need any changes because it already depends on the `AccountRepository` abstraction rather than a specific storage class. In the original monolithic `BankAccount` approach, adding a storage option could require changing the account class and risk affecting account behavior. This SOLID design keeps storage changes separate from account and notification responsibilities.
